# 疑難排解與踩坑紀錄

更新日期：2026-04-30

這份文件記錄這次實際重建 terminal 時踩到的問題。未來 agents 先看這份，可以少重複幾次同樣的痛。

## Windows Terminal 開啟就報 zoxide / Invoke-Expression 錯誤

症狀：

```text
Invoke-Expression: Cannot bind argument to parameter 'Command' because it is an empty string.
Invoke-Expression: Missing closing '}' in statement block or type definition.
```

根因：

`zoxide init powershell` 會輸出多行 PowerShell 腳本。若直接：

```powershell
zoxide init powershell | Invoke-Expression
```

PowerShell 會把每一行分開丟進 `Invoke-Expression`。空白行會造成 empty string 錯誤，函式區塊被拆開會造成 missing `}`。

正確寫法：

```powershell
function Invoke-ZoxideInit {
  param([switch]$Force)

  $zoxide = Get-Command zoxide -ErrorAction SilentlyContinue
  if (-not $zoxide) { return }

  if ($Force) {
    $global:__zoxide_hooked = 0
  }

  $zoxideInit = (& $zoxide.Source init powershell) -join "`n"
  if (-not [string]::IsNullOrWhiteSpace($zoxideInit)) {
    Invoke-Expression $zoxideInit
  }
}
```

驗證：

```powershell
. $PROFILE
Get-Alias z
zoxide --version
```

## Oh My Posh 切 theme 後 zoxide hook 可能被覆蓋

症狀：

- `z` alias 還存在，但 zoxide 不再穩定紀錄新路徑
- `omp-theme preview/set/next/prev/tour` 後行為變怪

根因：

Oh My Posh 會重建 `prompt`。zoxide 也會把 hook 掛在 `prompt` 上。

處理：

1. 先 `Invoke-OmpInit`
2. 再 `Invoke-ZoxideInit -Force`
3. `omp-theme` 每次重載 Oh My Posh 後，也跑 `Invoke-ZoxideInit -Force`

## winget 裝完工具，但目前 tab 找不到 zoxide/fzf/broot

症狀：

```powershell
Get-Command zoxide,fzf,broot
```

在舊 PowerShell tab 找不到新工具。

根因：

winget portable package 會更新 User PATH，但已開啟的 shell 不一定立刻吃到。這不是安裝失敗。

處理：

1. 先開新的 Windows Terminal tab 測。
2. 若仍失敗，再檢查 User PATH：

```powershell
[Environment]::GetEnvironmentVariable("Path", "User") -split ";"
```

3. 驗證 winget package 是否存在：

```powershell
winget list --id ajeetdsouza.zoxide --exact
winget list --id junegunn.fzf --exact
winget list --id Dystroy.broot --exact
```

## broot 樣式還是藍色

症狀：

broot 可啟動，但看起來像預設 `dark-blue`，不是暗底、米色文字、灰綠目錄線。

根因：

broot 有自己的 skin，不會自動吃 Windows Terminal 的 `Warm Sand` 色票。必須另外寫入：

```text
%APPDATA%\dystroy\broot\config\skins\codex-muted-green.hjson
```

並在：

```text
%APPDATA%\dystroy\broot\config\conf.hjson
```

把 dark skin import 指向：

```hjson
file: skins/codex-muted-green.hjson
```

不是：

```hjson
file: skins/dark-blue.hjson
```

repo 內的來源檔：

```text
skills/terminal-navigation-tools/references/codex-muted-green.hjson
```

驗證：

```powershell
Test-Path "$env:APPDATA\dystroy\broot\config\skins\codex-muted-green.hjson"
Select-String "$env:APPDATA\dystroy\broot\config\conf.hjson" -Pattern "codex-muted-green"
broot --conf "$env:APPDATA\dystroy\broot\config\conf.hjson" --version
```

## broot --install 權限失敗

症狀：

```text
Installation check resulted in Permission Denied.
Please relaunch with elevated privilege.
IO Error 用戶端沒有這項特殊權限。 (os error 1314)
```

根因：

broot 嘗試建立 launcher symlink，但 Windows 權限不允許。

處理：

- 不要改用其他工具繞過。
- 優先請使用者用提升權限重跑 `broot --install`。
- 若使用者不想提升權限，可用 broot 官方輸出作為 fallback：

```powershell
broot --print-shell-function powershell
```

把輸出的 `br` function 放進 profile 的互動式區塊，並設定：

```powershell
Set-Alias b br
```

## Warm Sand、Oh My Posh theme、broot skin 的差異

這三個不是同一層：

| 名稱 | 控制範圍 | 目前預設 |
| --- | --- | --- |
| Windows Terminal `colorScheme` | terminal ANSI 顏色 | `Warm Sand` |
| Oh My Posh theme | prompt 外觀 | 使用者用 `omp-theme` 自選 |
| broot skin | broot UI 內部顏色 | `codex-muted-green.hjson` |

不要用 Oh My Posh theme 判斷 broot 是否套色成功。也不要只看 Windows Terminal scheme 判斷 broot 內部顏色。

## 最小健康檢查

開新的 Windows Terminal tab 後執行：

```powershell
. $PROFILE
omp-theme current
Get-Alias z
Get-Command rg,fzf,zoxide,broot,codex,copilot
Test-Path "$env:APPDATA\dystroy\broot\config\skins\codex-muted-green.hjson"
Select-String "$env:APPDATA\dystroy\broot\config\conf.hjson" -Pattern "codex-muted-green"
```

如果這些都通過，再做肉眼確認：

- Windows Terminal 背景是暗綠灰
- prompt 是使用者選好的 Oh My Posh theme
- broot 是暗底、米色文字、灰綠目錄線
- `b` 可啟動 broot
- `Shift+Enter` 可從 broot 回 shell 並切到選取資料夾
